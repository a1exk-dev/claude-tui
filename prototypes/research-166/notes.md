# Does the /ctui menu survive a settings reload? (#166)

PROTOTYPE, throw away. Claude Code 2.1.292, `--model haiku`, the installed ctui 0.3.0 beside it.

- `spike/`: plugin `r166` with ctui-like `userConfig` (four `<id>_enable` booleans, `limits_cost`, `limits_cost_monthly` with `min: 0`, `theme`). It registers `/r166` with `immediate: true` and opens one pane `menu` with levels `top` → `plugins` → `limits`, and `top` → `themes`. The level, the filter text and each level's last pick live in `$.state` (`r166.menu`). Every module load logs a 4-letter generation id, shown in the pane title.
- `run.sh <name> <cols> <rows> <fullscreen 1|0>` copies `spike/` to `run-<name>/` and starts it in tmux `r166-<name>`. `cap.sh <name> <label>` captures. The log of each run is `log-<name>.txt`, and captures are `capture-<name>-<label>.{txt,ansi}`.
- Runs a–h and k are fullscreen at 160×45. Runs i and j are on the main screen (`CLAUDE_CODE_NO_FLICKER=0`) at 120×40.
- `$.config.set` writes `pluginConfigs["r166@inline"]` to `~/.claude/settings.json`. It was restored from `settings.backup.json` afterwards.

## Answers

| Question | Answer |
|---|---|
| Does the pane survive a reload? | **Yes.** Each `$.config.set` reloads the module (new generation id) and fires `session.start` again, and `$.ui.panes()` there lists `menu` shown, placed and focused. Three toggles in 4 s (run c), a Theme pick (f), `limits_cost` (f) and a number (f, j) all left the pane open, and the keys stayed in it. The re-run `session.start` registers `/r166` again without error. |
| Level and highlight after it | Kept from `$.state`, which survives the reload. The module-level variables reset. The Select comes back as the pick left it: collapsed (`● context ▾`) on the picked row, and Enter or an arrow reopens it there. A pick collapses a Select with no reload too (the no-op row, run b), so that is Select behaviour, not the reload. Highlight moves raise no event, so only a pick can be restored. |
| Flicker | None. Frames sampled every 15 ms across a toggle (run k) go from old drawing to new drawing with no blank or Sidebar frame in between, about 50 ms apart. |
| Transcript rows | **One 2-line row per change**, fullscreen and main screen: `● r166: options changed — reloaded (7 hooks: session.start, command.run, ui.render, ui.select, ui.focus, ui.input, ui.close)`. Changes are not merged. A `$.config.set` the engine denies adds no row and no reload. |
| Esc back one level | **`{}` does not refuse.** The engine skips the hook (`ui.close hook skipped: returned the wrong shape (neither { value } nor { deny })`) and closes. That happened sync or async, origin `person` or `plugin` (runs c–e). **`{ deny: '…' }` refuses**: the pane stays and the parent level draws. Nothing is printed. But the keys go back to the prompt (`isFocused: false`), and `$.ui.focus` is denied (`that site does not hold the keyboard`). A second `$.ui.open({ id, focus: true, closeOnEscape: true })` on the open id takes the keys back, and the parent Select draws open on its last pick (run h, main screen run i). Esc works this way from a collapsed Select, an open one, and a focused Input. Fallback that also works: let the close pass and re-open from the hook (13 ms, no frame without the pane at 30 ms sampling, run f). |
| Without `closeOnEscape` | Esc only collapses the Select and hands the keys to the prompt. No `ui.close` is raised, and the pane is left with no keyboard (run d). |
| Type-to-filter Themes | **Works.** An `Input` (`autoFocus`) above the Select raises `ui.input` `change` per keystroke, and redrawing the Select from the filter in `$.state` narrows the list (`ka` → Kanagawa, Osaka Jade). An empty list is replaced by a `no match` line, and the field keeps focus. **Down** moves focus from the field into the list and opens it. **Shift+Tab** goes back to the field. Tab past the list leaves the pane (keys to the prompt). Typing while the list is focused does nothing. A pick keeps the filter across the reload (run f, main screen run i). |
| Number field | **Works.** Tab from a Select reaches the `Input`. Down inside an open Select stays in the list. Typing appends to the drawn value (`100` + `abc` = `100abc`), and Enter submits the text then empties the field. `Number('250')` passed to `$.config.set` saved a number, reloaded, and the field kept focus showing `250`. `-5` came back as `{ deny: 'r166 monthly doesn't accept "-5". It takes a number between 0 and ∞.' }` in 2 ms, with no reload. `abc` is ctui's to reject. Either way the field is left empty. |
| Hook order | Change the level after `next(e)` in `ui.select` and `ui.input`. A state write first redraws the pane, the Select or Input is dropped, and the bottom handler throws `no handler is held under handle N`. |
