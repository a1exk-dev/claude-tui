# ctui v0.1 build spec

> Superseded in part by ctui 0.4.0 (#168): the one `/ctui` menu replaced the `/ctui:*` commands, and the `git` header and `versions` footer lost their enable settings. The text below records the earlier state.

This spec covers ctui v0.1 for the terminal: the **Sidebar** with all seven **Sidebar plugins**, the agent and shell toasts, `/ctui:theme`, `/ctui:plugins:enable|disable`, and the main-column skin from the renders in `docs/design/`. It targets Claude Code 2.1.288. It came out of the map [#3](https://github.com/a1exk-dev/claude-tui/issues/3) and its closed tickets.

`MEMORY.md` holds the decisions, and this spec does not repeat them. Each slice below names the `MEMORY.md` entries it applies, by heading. This spec adds the build order, the module layout, the parts no ticket covered (the `git`, `context`, `limits` and `versions` Sidebar plugins, and the look of each row), the test plan and the known differences. If this spec and `MEMORY.md` disagree, stop and ask the human.

## Rules for every slice

- Build the slices in order. Each slice is one `feature/<slice>` branch and one pull request into `develop` (AGENTS.md).
- Every slice applies "Sidebar plugins are pure; only `register.tsx` touches `$`" and "Tests cover real usage: unit tests per module, scenario tests through hooks, live checks for the rest".
- A slice is done when all four hold:
  - the check runner exits 0 (`scripts/check.sh` in slice 1, `scripts/check.ts` afterwards);
  - the slice's tests listed below exist and pass in `claude plugin test ctui`;
  - its live checks are in `docs/testing/live-checks.md` and were run on the pin;
  - the pull request template names the live-check sections that ran.
- Spike against `claude --plugin-dir ./ctui` in a fullscreen terminal 110 or more columns wide. Throwaway code goes in `prototypes/`.

## Module layout

| File | Role |
|---|---|
| `ctui/hooks/register.tsx` | Every `on(...)` hook, every `$` call, the data loaders, the 1 s tick and the toast queue. |
| `ctui/hooks/config.ts` | Pure. Turns the flat `options` into `{ <id>: { enable, folded? }, agents: { toasts }, todo: { tools }, theme }`. |
| `ctui/hooks/sidebar.tsx` | Pure. The Sidebar body: git header, section headers with fold buttons, list caps, the scroll window, the versions footer. |
| `ctui/hooks/pickers.tsx` | Pure. The picker pane's `Select`. |
| `ctui/hooks/commands.ts` | Pure. Decides each `/ctui:*` outcome: write, one-line text, or picker. |
| `ctui/hooks/tasks.ts` | Pure. The `Task` model and its transitions, `parseTaskNotification`, failure-reason mapping, toast texts, and the queue's ordering rules. |
| `ctui/hooks/git.ts` | Pure. Parses the git output for the header. |
| `ctui/hooks/mcp.ts` | Pure. MCP rows from the tool list, the disabled list, the previous rows and the time. |
| `ctui/hooks/format.ts` | Pure. Elapsed time, token counts, reset times, level colors, mode labels, and the `model · effort` label and its fit test. |
| `ctui/hooks/skin/*.tsx` | Pure. The trees for the `AssistantMessage`, `UserMessage`, `ToolUse` and `TurnDuration` rewrites. |
| `ctui/plugins/<id>/index.tsx` | Sidebar plugin views. |
| `ctui/types/index.d.ts` | The `$.state` contract below. |
| `ctui/tests/*.test.ts(x)` | Tests for `claude plugin test ctui`. |

Pure modules take the element table from `$.ui.resolve(e)` as a value where they draw.

### `$.state` contract

```ts
type Task = {
  id: string                      // agentId, backgroundTaskId or Workflow taskId
  kind: 'agent' | 'shell' | 'workflow'
  type: string                    // subagentType, 'shell' or 'workflow'
  label: string                   // description, the command's first line, or workflowName
  parent?: string                 // parent agent id or Workflow taskId: draws └
  transcriptDir?: string          // workflow only
  status: string                  // running | completed | failed | killed | other engine words
  startedAt: number               // $.clock.now()
  endedAt?: number
  reason?: string                 // short failure reason
}

interface PluginState {
  ctui: {
    folded: Record<string, boolean>     // per Sidebar plugin; a new session seeds it from <id>_folded
    expanded: Record<string, boolean>   // list caps (mcp, todo, agents)
    scroll: number                      // Sidebar section offset, in rows
    now?: number                        // written by the tick while a timer shows
    tasks: Record<string, Task>
    git?: GitSnapshot
    usage?: { context; rateLimits; cost? }   // as $.session.usage() answers
    month?: { month: string; session: string; usd: number }   // the ended sessions' cost in the local month
    mcp: McpRow[]
    todo?: { tools: 'task' | 'todowrite' | 'none'; items: TodoItem[] }
    activeForms: Record<string, string> // todo task id → activeForm
    model?: string
    effort?: string | null           // null: the model takes no effort
    turns: { durationMs: number; mode: string; model: string }[]
    todoEnvSet?: boolean
    versions?: { ctui: string; claude: string }
  }
}
```

Keep every record in `turns` for the session: old footers redraw on scroll. Write a field only when its value changed.

### The 1 s tick

`session.start` starts one `$.clock.every(1000)`. Each tick:

- polls `$.agent.list()`, `$.tool.list()`, `$.session.model()` and `$.settings.read()` (effort);
- re-reads `~/.claude.json` when its mtime changed (`mcp`);
- merges the `/clear` and `/resume` carry-over;
- reloads `$.session.usage()` when `$.state` has no `usage` (after `/clear` or `/resume`);
- refreshes git every 5th tick;
- drops ended tasks 8 s after `endedAt`;
- writes `now` while a running timer or an ended row shows.

Run a loader only when an enabled Sidebar plugin `needs` its data. The tick never waits on a git run that's still going: skip that refresh.

## Slices

### 1. Tooling

Apply "One pinned Claude Code version: devDependency, vendored types, tested-versions table" and "Tests cover real usage".

- Add `"@anthropic-ai/claude-code": "2.1.288"` (exact) to the root `devDependencies`.
- Write `scripts/check.ts`, run as `node scripts/check.ts`: Node strips the types, so there's no build step. It runs:
  - `tsc -p .`;
  - `node_modules/.bin/claude plugin validate ctui --strict` and `validate . --strict`;
  - `claude plugin test ctui`;
  - every consistency check from `check.sh`, plus the README-pin and `COMPATIBILITY.md` checks;
  - `typos`, with a warning when it isn't installed, as now.
  It fails when `node_modules/.bin/claude` is missing.
- Delete `scripts/check.sh`. Update AGENTS.md "Checks", `check.yml` and every doc that names `check.sh`.
- Add `ctui/COMPATIBILITY.md` (header only) and the README line `Tested with Claude Code 2.1.288 ([all tested versions](COMPATIBILITY.md)).` Add `COMPATIBILITY.md` to the `files` whitelist.
- Add `docs/testing/live-checks.md` with the six section headings from the MEMORY entry, a root `CONTRIBUTING.md` and `.github/pull_request_template.md`.
- Tests: one test that mounts every registry view with empty data on `terminal`.
- Live checks: none.

### 2. Sidebar frame, git header, versions footer

Apply "The Sidebar adapts to the dock's engine chrome", "The Sidebar shows only when docked, and the person can't close it", "Sidebar colors inherit the Claude Code theme", "Plugin settings are flat `userConfig` keys" and "The `versions` footer shows no update icon".

- Add the `<id>_folded` booleans (default `false`) for `context`, `limits`, `mcp`, `todo` and `agents`. The header and footer don't fold.
- Section header row: a plain `Button`, `▾`/`▸` dim, then the title in bold. When expanded, the right side shows the section's count. When folded, it shows the section's summary (below), dim and right-aligned.
- `git` header, from `git status --porcelain=v2 --branch`, `git stash list` and `git diff --numstat HEAD`, run through `$.process.run`. It refreshes at `session.start`, every 5 s, and after an Edit, Write, NotebookEdit or Bash `tool.call` returns.
  1. The cwd, bold, with the home directory shown as `~`.
  2. `⎇ <branch>`, or `⎇ <short sha>` when detached.
  3. `↑<ahead> ↓<behind>` when there's an upstream; then, only when non-zero, `+<staged>` `success`, `!<modified>` `warning` (conflicts count here), `?<untracked>` `inactive`, `≡<stashes>` `suggestion`. Leave the row out when it's empty.
  4. `+<added>` `success` `-<removed>` `error` then `lines changed` dim, summed from the numstat; binary files count 0. Leave the row out when both are 0. On an unborn branch, the numstat fails: treat it as 0.
  Outside a repo, draw only row 1.
- `versions` footer: `claude cli: <version> │ ctui: <version>, <Theme name>` on one row where it fits the body width, else `claude cli: <version>` and `ctui: <version>, <Theme name>` on two; labels muted, the `│` faint. The Theme name is the Theme file's `name`, or `inherit`. ctui's version comes from `${$.plugin.root}/.claude-plugin/plugin.json`, read once per `session.start`, and Claude Code's from `$.session.version()`.
- Tests:
  - unit: `git.ts` on captured porcelain output (clean, ahead/behind, detached, conflicts, no upstream);
  - unit: `sidebar.tsx` row slicing, `↑ more`/`↓ more`, caps, and the footer on the last row;
  - scenario: `SessionMode` at fullscreen 110+ opens the pane, and below 110 or off fullscreen it doesn't;
  - scenario: `placement: 'inline'` closes it, a `person` close is denied, and `ui.scroll` is answered.
- Live checks: Sidebar docking, and Sidebar layout and scroll.

### 3. `context` and `limits`

- Data: `$.session.usage()` at `session.start`, then `session.measure` (observe, `return next(e)`) for every change. After `/clear` or `/resume`, the tick reloads it.
- Level colors for bars and percents: below 50 `success`, below 85 `warning`, otherwise `error`.
- Bars are `━` cells: filled ones in the level color, the rest `inactive`. A bar fills its row minus 5 columns, where the percent sits right-aligned.
- `context`, expanded:
  - the bar and `<percent>%`;
  - `<tokens> / <window> tokens` dim (`18,402 / 200k tokens`).
  - Before the first response, `tokens` is absent: draw `0%` and `0 / 200k tokens`.
  - Folded: `9%`.
- `limits`, expanded: the cost block, then one block per window, in the order `five_hour`, `seven_day`, `spend_limit`, labelled `5h`, `week`, `spend`. Every amount puts `$` after the digits.
  - Row 1: the label, the bar, then the percent. Past 100, draw a full bar in `error`.
  - Row 2, dim and indented under the bar: `resets in 2h 17m`. When the reset is more than 24 h away, `resets in 3d 4h, Mon 09:00` (local time, 24-hour).
  - Leave out row 2 when `resetsAt` is absent.
  - The cost block (`limits_cost`): `auto` shows it unless Claude Code reports a `five_hour` or `seven_day` window (a plan; `spend_limit` alone isn't one), `on` always, `off` never; never when `cost` is absent. Row 1 is `cost`, the bar and the percent of this month's cost against `limits_cost_monthly`: every ended session's last `cost-state` in a transcript last written this local month, cached per session in `$.store`, plus the live session's cost. It shows once the first scan is done; row 2 reads `62.00$ of 100$`. Over the limit: a full `error` bar, the real percent (`134%`) and `134.00$ of 100$`. With limit 0: the bar always empty, no percent, and row 2 `62.00$`.
  - With no blocks (no windows and no cost block), draw one dim `no limits reported`.
  - Folded: the cost in whole dollars, then each window's percent, joined by ` · `: `62$ · 5h 34% · wk 81%`, `62$ · spend 41%`, `12$`, `5h 34% · wk 81%`, or nothing.
- Tests: unit views with sample usage, `format.ts` (tokens, resets); scenario: `session.measure` moves the rows.
- Live checks: Sidebar layout.

### 4. `mcp`

Apply "The `mcp` Sidebar plugin reads live tools and the disabled list; it never probes".

- Row: glyph in its color, the label, then the state text right-aligned (`22 tools` dim, `needs auth`, `connecting`, `down`, `off`).
- Folded summary: each glyph present, with its count, in its color, in the order `●`, `!`, `◐`, `✕`, `○` (`● 5 ✕ 1 ○ 1`).
- Tests:
  - unit: `mcp.ts` for each state change, including the `MCP_TIMEOUT` hand-off from `◐` to `✕`;
  - scenario: a hand-written `~/.claude.json` with a disabled list drives `off`.
- Live checks: Sidebar layout.

### 5. `todo`

Apply "The `todo` Sidebar plugin turns the task tools on by default" and the map decision for #10 (read with `TaskList`, keep `activeForm` from the `TaskCreate`/`TaskUpdate` inputs, fall back to `TodoWrite`).

- Rows in list order, leaving out `deleted`:
  - `✓` `inactive` with dim text for `completed`;
  - `◐` `warning` with default text for `in_progress`, showing its `activeForm` when known;
  - `○` `inactive` for `pending`.
- Header: `<completed>/<total>`. Folded: `2/8 · <in_progress item>`, or `2/8` when nothing is in progress.
- Tests:
  - unit: views;
  - scenario: `TaskCreate`/`TaskUpdate` through the drivers draw rows;
  - scenario: no task tools draws each hint;
  - scenario: `session.start` sets and unsets `CLAUDE_CODE_ENABLE_TODO_TOOLS` as the entry says.
- Live checks: Sidebar layout.

### 6. `agents` and toasts

Apply "Agent and shell events go to toasts, the live list goes to the sidebar", "Task ends come from notifications; running tasks carry across `/clear` and `/resume`", "A Workflow run is one task row; teammates stay hidden", and the map decision for #13 (failure reasons).

- Rows: the glyph, then the name, then the elapsed time right-aligned and dim.
  - Running: `◐` in `warning`, `<type>` then ` · <label>` dim, truncated at the end.
  - Shell: `$ <label>`.
  - Workflow: `⚙ <workflowName> workflow`.
  - Nested under a parent: `└ ` with 2 more columns of indent.
- Ended rows show for 8 s: `✓` `success`, or `✗` `error` with ` · <reason>`.
- Empty: one dim `nothing running`. Header: `<n> running`. Folded: `◐ 5 running`, or `nothing running`.
- Elapsed: `21s`, `1m 15s`, `15m 03s`, `1h 02m`.
- Toast texts, one line each, with newlines folded to spaces:
  - `◆ <type> started: <label>`
  - `$ <command's first line> started in background`
  - `◆ workflow started: <workflowName>`
  - `✓ <type> done · <label> · <elapsed>`; a shell's type is `shell`
  - `✗ <type> failed: <reason>`, or `✗ <type> failed` with no reason
  - `✗ <type> killed` for a model TaskStop
  - A `/tasks` kill and a nested workflow shell raise none.
- Tests:
  - unit: `parseTaskNotification` on the captured strings from #13, #14 and #15;
  - unit: the queue's ordering (end before start, an end drops its own waiting start) and its 2100 ms pacing under `mock.clock`;
  - unit: reason mapping and views;
  - scenario: `agent.spawn` gives a row and a start toast; a notification gives done;
  - scenario: `classic.StopFailure` gives the reason;
  - scenario: a background Bash gives a shell row; a `queued_command` kill gives `killed` and no toast;
  - scenario: the `/clear` carry-over;
  - scenario: a Workflow row with a nested shell;
  - scenario: a teammate is filtered out;
  - scenario: `agents_toasts` off enqueues nothing.
- Live checks: toasts, and Sidebar layout.

### 7. Commands and pickers

Apply "Plugin name is `ctui`" and "`/ctui:*` commands stay quiet on success; a bare command opens a picker pane".

- The picker's `columns` is the Sidebar's current width (42 or 53).
- Tests:
  - unit: `commands.ts` for every outcome in the entry;
  - scenario: each command through `$.command.run`, with the test's own `config.set` hook standing in for the engine (#6), including a `{ deny }` and the missing `ctui.theme` row.
- Live checks: commands and pickers, and `claude -p`.

### 8. Transcript rewrites

Apply "`UserMessage` rewrites draw the person's own prompts only" and "Tool rows: glyph rows for Read, Edit, Write and Bash; results stay Claude Code's".

- `AssistantMessage` (map decision for #18): `Box({ paddingLeft: 2, children: [await next({ ...e, props: { ...e.props, isFirstOfReply: false } })] })` on every block. There's no setting for it.
- Tests:
  - unit: tool-row subjects and summaries, for each state;
  - scenario: `$.ui.mount` of `UserMessage` (`composer` draws the bar; `task-notification` passes through), `ToolUse`, `ToolGroup` and `AssistantMessage`.
- Live checks: render-site rewrites, fullscreen and main screen.

### 9. Line under the prompt and turn footer

Apply "The line under the prompt: `model · effort` is a `SessionMode` label" and "The turn footer: prefix the turn's mode and model to Claude Code's `word`".

- The `SessionMode` hook is the one from slice 2, so the viewport watcher and the label share it.
- The fit test measures the terminal's width: while the Sidebar is docked, `viewport.columns` excludes the dock (checked in #55, recorded in that MEMORY entry).
- Tests:
  - unit: the fit formula, the mode labels, and the effort order;
  - scenario: `turn.step` and `turn.complete` then a `TurnDuration` mount draws the prefix; a mount with no matching record passes through; `aborted` stores nothing.
- Live checks: render-site rewrites.

### 10. Docs, then release 0.1.0

- `docs/configuration.md`, linked from `ctui/README.md` by its GitHub URL. It covers:
  - every setting, and the Sidebar plugins with their options;
  - the example CLI theme ("Sidebar colors inherit the Claude Code theme", including `promptBorder`, which also colors the `┃` bar);
  - the "Main background" section ("The prompt box and main background stay Claude Code's").
- Finish `ctui/README.md`:
  - the Task tools disclosure ("The `todo` Sidebar plugin turns the task tools on by default");
  - the requirements in "Publish to Anthropic's plugin directory and to npm";
  - the fullscreen requirement (the `"tui": "fullscreen"` setting or `CLAUDE_CODE_NO_FLICKER=1`, 110+ columns);
  - a short known-differences note that links here.
- Then `release/0.1.0` into `main`: follow the release bullets of "Publish to Anthropic's plugin directory and to npm". The human merges it and the tag is `v0.1.0`.
- Live checks: the full list on the pin.
